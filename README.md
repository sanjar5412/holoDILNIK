# Freshloop

MVP веб-приложения для контроля продуктов дома, сроков годности и планирования меню.
Сделан для **Notar Academy Selection**, тема — **Food Waste at Home**.

Freshloop помогает не забывать о том, что уже лежит в холодильнике: показывает
продукты с истекающим сроком, собирает меню из имеющихся запасов и честно
перечисляет недостающие ингредиенты.

## Готовый архив и загрузка на GitHub

В корне проекта лежит `freshloop.zip` — исходники без `node_modules` и `.next`.

1. Распакуйте архив в отдельную папку.
2. Создайте пустой репозиторий на GitHub (без README и .gitignore).
3. Загрузите **содержимое** папки в репозиторий:

```bash
cd freshloop
git init
git add .
git commit -m "Freshloop MVP"
git branch -M main
git remote add origin https://github.com/ВАШ-АККАУНТ/freshloop.git
git push -u origin main
```

4. В Vercel выберите **Add New → Project**, импортируйте репозиторий и нажмите
   **Deploy**. Переменные окружения не нужны, Framework Preset определится
   как Next.js автоматически.

Альтернатива без GitHub: распакуйте архив, выполните `npm install` и
`npm run build`, затем загрузите папку через Vercel CLI (`npx vercel`).

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). При первом запуске
приложение загрузит демо-набор с продуктами и меню на сегодня.

Другие команды:

```bash
npm run build      # production-сборка
npm start          # запуск production-сборки
npm run typecheck  # проверка TypeScript
```

Требуется Node.js 20.9 или новее.

## Что работает

- **Обзор** — количество продуктов, продукты «использовать скоро», меню на
  сегодня, ближайшие напоминания и сводка предотвращённых отходов.
- **Запасы** — поиск по названию, фильтры по статусу срока, категории и месту
  хранения; редактирование, удаление и отметка «использовано».
- **Добавление и редактирование продукта** — валидация обязательных полей,
  проверка дат, быстрые кнопки популярных продуктов, заметки.
- **Меню** — план на сегодня, 3 дня или неделю, блюда из локальной библиотеки
  рецептов с приоритетом скоропортящихся продуктов. Для каждого блюда видны
  используемые продукты и недостающие ингредиенты. Можно заменить блюдо,
  отметить его приготовленным и списать продукты, скопировать список покупок.
- **Напоминания** — просроченные и скоро истекающие продукты, настройка
  горизонта предупреждения (1–7 дней), отметка «выполнено» и возврат
  выполненных напоминаний.
- **О проекте** — объяснение ценности, ограничения MVP, управление данными:
  скачать JSON-копию, удалить демо-данные, очистить всё.

Все основные кнопки и формы рабочие: нет кнопок-заглушек и «мёртвых» ссылок.

## Стек

- **Next.js 16** (App Router) + **React 19**
- **TypeScript** в строгом режиме
- **Tailwind CSS 4** с дизайн-токенами в `src/app/globals.css`
- `next/font` — Lora для заголовков, Inter для интерфейса (оба с кириллицей)
- Без UI-китов и икон-пакетов: компоненты и SVG-иконки собственные

## Данные и приватность

MVP **не использует серверную базу данных**. Запасы, меню, настройки и история
хранятся в `localStorage` браузера под ключом `freshloop.state.v1`.

- Данные не отправляются на сервер и не синхронизируются между устройствами.
- Состояние версионируется; при чтении выполняется безопасная валидация
  каждого поля. Повреждённый JSON сохраняется в резервный ключ
  `freshloop.state.corrupt`, после чего приложение стартует с демо-набора.
- При очистке хранилища браузера данные исчезнут.
- Это осознанный MVP-вариант. Для продакшена нужны серверная БД и авторизация.

## Демо-данные

При первом открытии загружается 17 продуктов с относительными сроками годности
(включая один просроченный), история использования и меню на сегодня. Демо-данные
можно удалить в разделе **О проекте → Данные и приватность**, не затрагивая
добавленные вами продукты. Демо-оценка денег считается по средним ценам
категорий (`src/lib/domain/prices.ts`), а не по реальным чекам.

## Структура проекта

```
src/
  app/                  страницы App Router
    page.tsx            обзор
    inventory/          запасы
    menu/               меню
    reminders/          напоминания
    about/              о проекте и данные
  components/
    layout/             каркас, навигация, скелетон
    products/           диалог продукта и провайдер
    inventory/          строка продукта
    menu/               карточка блюда и списание продуктов
    ui/                 кнопки, поля, модалка, тосты, бейджи, иконки
  config/brand.ts       название и описание продукта в одном месте
  lib/
    domain/             чистые функции: статусы, меню, напоминания, валидация
    storage/            localStorage-репозиторий и демо-набор
    store/              React-контекст и действия
```

Бизнес-логика отделена от UI: модули в `src/lib/domain` не зависят от React.
Репозиторий в `src/lib/storage` можно заменить на серверный, не переписывая
страницы.

## Как подбирается меню

1. Для каждого рецепта ингредиенты сопоставляются с продуктами по названиям
   (словарные основы: «яйц» → «Яйца»).
2. Просроченные продукты в меню не предлагаются.
3. Блюдо получает баллы за покрытие ингредиентов и за использование продуктов
   с близким сроком.
4. На каждый приём пищи выбирается один из лучших вариантов; случайность
   управляется seed, поэтому «Пересобрать» даёт другой, но воспроизводимый план.
5. «Приготовлено» открывает окно списания: можно уменьшить количество или
   оставить продукт в запасах.

Внешние API и ИИ не используются — в интерфейсе это указано явно.

## Доступность

- Семантические заголовки, `label` у полей, `aria-invalid` и сообщения об ошибках.
- Нативные `<dialog>` с фокус-ловушкой, Esc и возвратом фокуса.
- Видимые состояния фокуса, контраст текста, статусы не только цветом.
- Уважение `prefers-reduced-motion`.
- Адаптивная навигация: боковая панель на десктопе, нижняя — на мобильных.

## Переменные окружения

Для запуска и деплоя **не требуются**. Секретов в клиентском коде нет.
Если вы захотите добавить интеграции, ключи должны храниться только на сервере
(Environment Variables в Vercel), а не в `NEXT_PUBLIC_*`.

## Деплой на Vercel

1. Загрузите проект в Git-репозиторий.
2. В Vercel нажмите **Add New → Project** и импортируйте репозиторий.
3. Framework Preset определится как **Next.js**; команды сборки менять не нужно
   (`npm run build`).
4. Environment Variables не нужны. Нажмите **Deploy**.

Приложение полностью клиентское, поэтому работает и как статический хостинг
Next.js. Серверная часть не требуется.

## Замена названия

Название, слоган и описание заданы в `src/config/brand.ts`. Логотип-лист и
основные цвета — в `src/components/ui/icons.tsx` и `src/app/globals.css`.
